# 阶段 5 报告：LangGraph Agent 编排（工具 / 重试 / 人工审批）

日期：2026-11-11

## 1. 状态机

```
START → plan ─┬─(无工具)──────────────→ respond → END
              ├─(读操作)──→ act ─────→ respond → END
              └─(写操作)──→ approval ─→ act ─→ respond → END
                             ↑ interrupt 挂起
                             └── resume(approved) 从断点继续
```

- `plan`：意图路由，决定调用哪个工具、参数是什么
- `approval`：写操作在此 `interrupt()`，把动作详情抛给调用方；人工确认后用 `Command(resume=...)` 恢复
- `act`：执行工具，失败重试 2 次（指数退避），仍失败则把错误带进回答节点
- `respond`：把工具结果交给模型润色成自然语言，保留关键数字

## 2. 工具清单

| 工具 | 类型 | 说明 |
|---|---|---|
| `get_leave_balance` | 读 | 查年假总额 / 已用 / 结转 / 剩余 |
| `get_ticket_status` | 读 | 查工单状态、负责人、剩余 SLA |
| `submit_leave_request` | **写** | 提交请假，需人工审批；带幂等键（工号+日期+天数） |

## 3. 测试结果（6 个场景）

| 场景 | 输入 | 结果 |
|---|---|---|
| 查余额 | 我还有几天年假 | ✅ 工具 `get_leave_balance`，回答「还有 9 天（额度 10、已用 3、结转 2）」 |
| 查工单 | T-1001 现在什么状态 | ✅ 返回处理中 / P1 / 王工 / SLA 剩 5 小时 |
| 提交请假 | 帮我请下周五的假 | ✅ 挂起，approval 里给出 `2026-11-20`、1 天；批准后生成 `LR-AC7AB2C1` |
| 拒绝审批 | 同上，resume approved=false | ✅ 「操作未完成：用户取消了本次操作」 |
| 工具失败 | 帮我请 20 天假（余额 9 天） | ✅ 重试 2 次后降级为「余额不足」，未抛 500 |
| 幂等 | 重复提交同一请假 | ✅ `duplicated=true`，返回原单号 `LR-AC7AB2C1` 并提示勿重复提交 |

## 4. 设计要点

1. **读写分离**：只有写操作进审批节点，读操作直接执行，避免“查个余额也要确认”的反人类体验。
2. **失败不 500**：工具异常被状态机接住，重试后转成用户可读的提示，这是 Agent 与“裸调 API”的关键差别。
3. **幂等键**：写工具用 `员工+日期+天数` 做键，重放请求不会产生两条记录——生产环境的 Agent 必须有这层保护。
4. **断点续跑**：`interrupt` 不销毁状态，resume 从 approval 节点继续，而不是重跑整个规划。

## 6. 已知限制

1. **Checkpoint 在内存**（`MemorySaver`）：进程重启后挂起的审批与线程状态丢失。生产需换 `PostgresSaver`。
2. **规划是规则+正则**，不是 LLM Planner：可控、便宜，但对复杂多步任务（“先查余额再决定请不请”）不够。仓库里的 `planner.py` 可作为升级路径。
3. **单工具单步**：目前一次只调一个工具，没做多工具串联与并行。
4. **审批无鉴权**：任何调用方都能批准，生产需接入登录态与权限模型。
