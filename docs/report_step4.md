# 阶段 4 报告：RAG 对话链路（引用 + 拒答）

日期：2026-11-11　　环境：Ubuntu 18.04 / Python 3.12.11 / RTX 3090

## 1. 链路

```
用户问题
  → 意图识别（规则）
  → 混合检索（向量 Top20 + BM25 Top20 → 加权 RRF）
  → Cross-Encoder 精排 Top5
  → 证据门禁：首条重排分 < 0.05 → 拒答（不调用大模型）
  → 组装提示（编号证据 + 最近 4 轮对话）
  → 大模型生成（deepseek-chat）
  → 解析 [n] 引用 → citations
```

## 2. 冒烟测试结果（6 题）

| 问题 | 期望 | 结果 | 引用数 | 延迟 |
|---|---|---|---|---|
| 年假有几天 | 应答 | ✅ | 1 | 1901 ms |
| P0 工单多久响应 | 应答 | ✅ | 3 | 1469 ms |
| 加班能调休吗 | 应答 | ✅ | 1 | 1912 ms |
| 公司有股权激励吗 | 拒答 | ✅ | 0 | 385 ms |
| 公司食堂在哪 | 拒答 | ✅ | 0 | 363 ms |
| 今天上海天气怎么样 | 拒答 | ✅ | 0 | 351 ms |

6/6 通过。拒答路径不调用大模型，延迟仅 ~0.36 s；正常回答 ~1.5–1.9 s（其中检索 ~0.3 s，其余为模型生成）。

## 3. 回答样例

问：P0 工单多久响应

> P0 工单需在 15 分钟内响应 [1][2]。
> 补充：P0 的解决时效为 4 小时内恢复 [1][2]；若超时，工单会自动升级至当班组长或上级主管 [2][5]。

问：公司有股权激励吗

> 抱歉，知识库中没有检索到与该问题足够相关的资料，我无法据此作答。建议把问题描述得更具体一些，或直接联系 HR／IT 确认。

## 4. 设计要点

1. **拒答优先于生成**：证据不足时直接返回固定文案，既避免幻觉也省 token（延迟从 1.9 s 降到 0.36 s）。
2. **阈值按重排 logit 校准**，不用余弦相似度：实测同域问题首条重排分 0.9+，域外为负值或接近 0，阈值 0.05 有足够裕度。
3. **引用可追溯**：citations 里带 result_id / document_id / chunk_index / score，前端可跳转到原文段落。
4. **降级开关**：请求体 `use_rag=false` 或 `.env` 的 `RAG_ENABLED=false` 可退回直连模型。

## 6. 已知问题

1. 拒答文案是硬编码中文，多语言场景需要 i18n。
2. 阈值 0.05 是在当前 34 块语料上定的，语料扩充后需重标。
3. citations 只解析 `[n]` 形式，模型若改写成「据资料 1」则解析不到，提示词已约束但无法保证 100%。
4. `/chat/stream` 仍是直连模型，没有接 RAG；流式 + 引用的实现留到阶段 5。
