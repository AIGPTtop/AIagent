## 3. 与扩充前对比

| 指标 | 34 块 / 16 题 | 114 块 / 40 题 |
|---|---|---|
| hybrid+rerank Hit@1 | 15/16 (93.8%) | 38/40 (95.0%) |
| keyword 语义型 MRR | 0.812 | 0.784 |
| 各模式差距 | 很小 | **明显拉开** |

扩充后最显著的变化：**BM25 在语义型问题上的 Recall@3 掉到 80%（16/20）**，而向量与混合都是 100%。这说明之前 34 块时“关键词检索也够用”是语料太小造成的假象——一旦不同文档出现相似词汇（“审批”“保留”“延期”到处都是），纯关键词就会互相干扰。

## 4. 延迟（114 块，单并发 8 次查询）

| 模式 | 均值 | P95 |
|---|---|---|
| vector | 135.4 ms | 142.4 ms |
| keyword | 3.3 ms | 4.1 ms |
| hybrid | 130.2 ms | 147.2 ms |
| hybrid+rerank | 337.9 ms | 348.5 ms |

相比 34 块时（vector 76.6 ms / hybrid 84.6 ms），检索耗时上升约 60%：主要来自 BM25 语料变大与向量集合变大，但仍在可接受范围。重排耗时基本不变（候选数固定 20）。

## 5. 结论

1. **重排的收益稳定**：40 题上 +2 Hit@1，语义型 +1；在两轮不同规模语料上都成立。
2. **混合检索的价值随语料增大而显现**：精确型靠 BM25 追平向量，语义型靠向量兜底，RRF 后两者都不吃亏。
3. **Recall@5 已饱和（40/40）**：说明当前题目对 top5 来说偏简单，后续要么加大 top1 竞争（更难的近义干扰项），要么把评测口径改为 Hit@1 + MRR 为主。

## 6. 已知问题

1. 语料仍是合成的，句子结构工整、主题边界清晰，比真实企业文档好检索；真实场景指标会低 10–20 个百分点。
2. 没有负样本（应有答案但库里没有的题），因此拒答率与误拒率没有纳入本次评测。
3. 40 题里语义型题目多为“换一种说法”，缺少跨文档推理题（需要合并两处信息才能回答）。
4. 延迟测试是单并发，未测并发下的检索退化。
